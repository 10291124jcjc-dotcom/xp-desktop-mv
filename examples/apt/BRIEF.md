## 0. 一句话目标

把一段 40.8 秒的 MV 剪辑，重做成一段**"粉色 Windows XP 桌面录屏"**：MV 里的人被抠出来，在桌面、窗口、任务栏上唱歌跳舞；所有界面元素都用代码画出来，每一次点击、弹窗、切换都卡在节拍上。

参考做法：@anabology 的 BLISS（Claude 用代码画 XP 桌面 + 抠像合成）。区别是：我们**不生成任何新素材**，所有人物画面都来自源视频。

---

## 0.5 核心创意：梗比画面重要

BLISS 能火，靠的不只是画面，而是**界面和科技热点之间的双关**：鼠标 Cursor = AI 公司 Cursor，Clippy 的"要帮你写信吗"变成"要帮你出门走走吗"。观众看一眼就懂，才会转发。

**我们的主梗：APT.（歌名）= `apt`（Linux 的装软件命令）**

一个粉色的 Windows 系统，里面却在不停冒出 Linux 的 apt，系统一路"抗拒"，最后被它"感染"。

**梗库（起点，你要扩充）**
- 双击"APT.mp3"→ 报错："Pinkdows 找不到 APT。是否通过 apt 安装？" [是] [否]，鼠标点"是"
- 黑色终端窗口按节拍逐字敲出：`sudo apt install apt` → 返回 `apt 已经是最新版本`
- 托盘气泡："发现新硬件：APT."、"您的公寓（APT.）已准备就绪"（APT 也是 apartment 的缩写）
- 连环报错："APT. 已在运行""APT. 没有响应""是否结束 APT.？" [结束] [继续蹦迪]
- 任务管理器：进程列表里全是 `apt.exe`，CPU 占用 100%
- 结尾：关机画面"现在可以安全地关闭计算机了"→ 最后半秒闪一行小字"正在安装 Ubuntu…"

**梗的规则**
1. **一眼就懂**：每条梗读一遍必须能懂，屏幕上每次出现的文字不超过 12 个汉字或 24 个英文字符。
2. **按好不好笑排序**：先列至少 20 条候选，标出"秒懂/要想一下/看不懂"，只用"秒懂"的。
3. **梗卡在拍子上**：报错弹出、终端回车、气泡出现都落在强拍。
4. **不写歌词**：梗只放在界面文案里，不改编、不引用歌词。

**→ 检查点 0**：开工前先给我看你扩充后的梗库，以及你建议的分镜调整。我确认后再开始。

## 2. 工作规则（重要，先读）

1. **所有文件都写在项目文件夹内。** 不要往项目外写任何东西，包括记忆、缓存、配置。BLISS 的制作中，一次往项目外写文件的权限确认让整条流程停了 9 小时。
2. **按阶段做，每个检查点停下来**，把预览图或预览视频给我看，我说"继续"再往下。
3. **不要下载任何素材**，比如图片、音效、字体文件。只允许安装 Python/Node 包和抠像模型。
4. **不要使用真实的 Windows logo、旗标和系统音效文件。** 界面全部用代码画，名字用戏仿：系统名叫 **"Pinkdows XP"**，公司叫 **"Macrosoft"**。
5. **歌词不要自己写进画面。** 源视频 17–25 秒本身带有手写歌词动画，需要歌词的地方直接用那段原画面。其他文字只用标题"APT."和界面文案（见第 7 节）。
6. 每一帧都必须是**时间 t 的纯函数**：给定 t 就能画出那一帧，方便任意重渲染、任意跳帧检查。

## 3. 环境准备

```bash
# 必需
ffmpeg            # Windows: winget install ffmpeg（本机是 Windows，命令用 PowerShell）
python3 -m pip install "rembg[cpu]" librosa soundfile numpy pillow opencv-python
npm i playwright  # 渲染用；用本机 Chromium 即可

# 抠像模型（rembg 首次运行会自动从 GitHub 下载）
#   主力：isnet-general-use
#   备选：u2net_human_seg（只抠人，杂物更少）
# 有 NVIDIA 显卡时用 rembg[gpu]，速度快 10 倍以上
```

项目结构：

```
project/
  BRIEF.md            ← 本文件
  source.mp4
  analysis/           ← 节拍、镜头、黑边检测结果、预览图
  clips/              ← 从源视频裁出的片段（已去黑边）
  mattes/<clip>/      ← 抠像结果，带透明通道的 PNG 序列

  shots/              ← 每个镜头的脚本（JSON）
  render/             ← 渲染出的帧
  out/
```

## 4. 阶段一：分析源视频

1. **节拍**：用 librosa 提取 BPM 和每一拍的时间，存成 `analysis/beats.json`。检查节拍是落在底鼓上还是踩镲上：如果整体偏早，就以底鼓为准重新对齐（BLISS 踩过这个坑，偏了 0.2 秒）。同时标出强拍、小节开头、段落切换点。
2. **镜头切点**：ffmpeg 场景检测（阈值 0.3）。已知切点约在：
   `0.17, 0.88, 6.10, 7.34, 8.94, 12.06, 12.83, 16.54, 16.97, 20.28, 23.03, 23.50, 25.54, 26.61, 29.83, 33.20, 36.34, 37.83, 39.43` 秒
3. **黑边**：以下片段四周带黑边，用 `cropdetect` 找到准确的裁切区域后裁掉：约 7–8.9 秒、16.5–25.5 秒、29.8–33.2 秒。
4. **预览**：生成每秒一帧、带时间码的拼图 `analysis/grid.jpg`。

**→ 检查点 1**：把 BPM、节拍图和拼图给我看。

## 6. 阶段二：抠像

需要抠的片段：**7.3–12.1（头像）、14.0–16.5、25.5–29.8、39.4–40.8**。

1. 先裁黑边，再把帧率降到 30fps，导出 PNG 序列。
2. 用 rembg 逐帧抠像，输出带透明通道的 PNG，存到 `mattes/<clip>/`。
3. **背景是粉色**，边缘容易残留粉边。处理办法：
   - 对边缘 2–3 像素做去色（despill），把偏粉的像素往中性色拉
   - alpha 收缩 1 像素，再轻微羽化
4. **实心核**：人物身体内部的 alpha 不能出现半透明的洞，特别是脚和黑色皮衣，必要时用形态学闭运算把洞补上。
5. **防闪烁**：对连续帧的 alpha 做时间平滑，比如取前后各一帧的中值，避免边缘抖动。
6. 头像那段（7.3–12.1）原画面就是剪纸风，抠完后**给头像加一圈 6 像素的白色描边**，保持剪纸贴纸的感觉。

**→ 检查点 2**：每个片段挑 3 帧，放在棋盘格和深色背景上各给我看一次。

## 7. 阶段三：Pinkdows XP 桌面引擎

用 JavaScript + HTML canvas 写一个**桌面引擎**，画布 1920×1080，提供 `drawFrame(t)`。

### 7.1 视觉风格：粉色版 Luna 主题
- **配色**：把 XP 的蓝色 Luna 主题整体换成粉色系，跟 MV 的粉色呼应。
  - 标题栏：热粉渐变 `#ff4fa0 → #d81b72`
  - 任务栏：同色系渐变
  - "开始"按钮：亮绿色换成黑色加粉色描边（呼应皮衣）
  - 窗口底色：`#fff0f6`
- **壁纸**：用代码画"粉色版 Bliss"：一道柔和的山坡曲线，山坡用粉色渐变，天空是浅粉到白，再加几朵程序化的云。**不使用真实的 Bliss 照片。**
- **字体**：Tahoma 风格的无衬线小字号，可用系统里已有的 Tahoma、Verdana 或 Arial；中文用系统黑体。
- **鼠标**：经典白色箭头，1 像素黑边，用代码画。

### 7.2 需要的组件
- 开机画面：黑底，中间是粉色的"APT."字样和"Pinkdows XP"字样，下方一条滚动的进度条
- 欢迎屏幕："欢迎"字样 + 两个用户头像（用抠好的大头贴）
- 桌面：壁纸、图标（我的电脑、回收站、APT.mp3、鼓.exe，图标用矢量画）、任务栏、开始按钮、托盘时钟
- 窗口（统一的 Luna 风格标题栏，带最小化、最大化、关闭按钮），分四种：
  - 媒体播放器：嵌入视频画面，带进度条和播放按钮
  - 记事本：嵌入视频画面，菜单栏写"文件 编辑 格式 查看 帮助"
  - 视频通话：两个人的名字分别叫"APT 1号"和"APT 2号"
  - 错误对话框：一个红色 × 图标 + 一行文字 + 按钮（按钮文字可自定义，用来放梗）
  - 终端窗口：黑底、等宽绿字或白字，光标闪烁，文字按节拍逐字敲出（专门用来放 apt 梗）
  - 任务管理器：进程列表 + CPU 占用曲线，曲线跟着音量跳
- 气泡提示：从托盘弹出的黄色气泡，里面放大头贴或一行梗
- 屏幕保护程序：全屏播放视频画面
- 关机画面："现在可以安全地关闭计算机了"（橙色字，黑底）

### 7.3 镜头脚本
每个镜头写成一个 JSON 脚本，存在 `shots/` 里：包含窗口的开启和关闭、位置和大小、鼠标路径、点击时间、视频片段的入点和出点。**所有时间点都对齐到 `beats.json` 的拍子上。**引擎负责把脚本编译成动画。

**→ 检查点 3**：用引擎渲染 5 张静帧给我看：开机、桌面、媒体播放器、错误对话框、关机。重点检查配色和质感，不对就先调到我满意再往下。

细节要求：
- 鼠标是主角之一，移动要有缓动，点击卡在拍子上，点击瞬间按钮有按下的效果。
- 窗口打开、关闭要有 XP 那种简单的缩放动画，时长不超过 4 帧。
- 视频画面放进窗口时保持原比例，四周留窗口边框，不要拉伸。
- 镜头之间不要用花哨的转场，硬切卡在拍子上。

### 8.1 分章制作 + 美术总监审核循环（BLISS 质量的关键）

BLISS 的每一章都要经过"制作 → 美术总监审核 → 修改 → 验证"，不是一次做完就交。我们照这个来。

**分章**：把分镜拆成 6 章，每章一个文件，放在 `shots/ch01.json` 到 `shots/ch06.json`：
1. 开机 + 欢迎（0.0–2.5）
2. 桌面 + 主梗登场（2.5–7.3）
3. 大头贴轰炸 + 注销（7.3–14.0）
4. 坐在任务栏 + 记事本（14.0–25.5）
5. 报错轰炸 + 视频通话（25.5–37.8）
6. 跳舞 + 关机（37.8–40.8）

**每一章的循环**：
1. **制作**：写这一章的镜头脚本，渲染低分辨率预览。从预览视频里每 0.25 秒抽一帧，拼成一张带时间码的拼图。
2. **审核**：派一个子 Agent 当"美术总监"。它**没看过制作过程**，只看拼图和本文档，按下面 5 项各打 1–10 分，并写出具体修改意见（哪一帧、什么问题、怎么改）：
   - 质感：像不像真的 XP 录屏，像素、字体、边框对不对
   - 节奏：动作是不是卡在拍子上，有没有拖沓
   - 梗：文字一眼能不能看懂，好不好笑
   - 抠像：有没有粉边、闪烁、破洞
   - 构图：画面是否拥挤，主体是否清楚
3. **修改**：按意见改。
4. **验证**：再派一个新的美术总监子 Agent 重新打分。

**通过标准**：5 项平均分 ≥ 8，且没有任何一项低于 6。最多循环 3 轮，3 轮还不过就停下来，把问题告诉我。

所有分数和意见记录在 `review_log.md`，每章一节。各章可以并行做，但最后要检查**章与章的衔接处**：每个切点前后各看 3 帧。

**→ 检查点 4**：渲染一版 480p 的草稿视频给我看节奏，附上 `review_log.md` 里每章的最终分数。

## 9. 阶段五：音效（可选）

- 主音轨 = 源视频原声，不做任何改动。
- 界面音效**用代码合成**，不要下载 Windows 原版音效：点击声是很短的"嗒"，弹窗声是短促的两音"叮咚"，错误声是低音"咚"。
- 音效放在拍子上，音量比原声低 12 dB 左右，人声段落里再压低一些。
- 先做无音效版，我看过草稿再决定要不要加。

## 10. 阶段六：渲染与检查

1. 用 Playwright 无头浏览器逐帧调用 `drawFrame(t)` 截图，1920×1080，30fps，输出到 `render/`。
2. ffmpeg 合成：
   ```bash
   ffmpeg -framerate 30 -i render/%05d.png -i source.mp4 -map 0:v -map 1:a \
     -c:v libx264 -crf 16 -pix_fmt yuv420p -c:a aac -b:a 192k -shortest out/APT_XP_v1.mp4
   ```
3. 自检清单：
   - [ ] 时长与源视频一致，音画同步（对照 3 个明显的鼓点检查）
   - [ ] 抠像没有粉边、没有闪烁、身体内部没有破洞
   - [ ] 所有窗口里的视频没有被拉伸
   - [ ] 没有出现真实的 Windows logo 或旗标
   - [ ] 生成 `out/contact_sheet.jpg`

**→ 检查点 5**：给我成片和拼图。

## 11. 我（导演）会在检查点给的意见类型

- **审美**：配色、质感、哪里太花、哪里太素
- **节奏**：哪里切得太快、哪里拖了
- **取舍**：哪段不要、哪段加长

我的意见会很短。拿不准的地方先做一个版本给我看，不要停下来问。
